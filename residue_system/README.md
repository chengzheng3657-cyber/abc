# 组织残留快检系统
Python 3.10及以上版本，仅使用标准库。采集图像、标定数据和检测报告通过HTTP端口交换；SQLite用于服务内部的数据保存。
## 运行
在当前目录运行：
```bash
python3 run_demo.py
```
运行器启动本机HTTP服务，客户端提交三组模拟标准品，再提交1.5 ng/mL的模拟试纸条图像，接收压缩报文并模拟接收网关转发，最后获取JSON报告。服务请求完成后退出。输出目录默认为系统临时目录下的 `residue-demo-v2`，其中包含 `summary.json`、`report.json`、`reconstruction.ppm` 及内部数据库。可指定输出目录：
```bash
python3 run_demo.py --output-dir ./run-output
```
长期运行服务和独立客户端：
```bash
python3 server.py --host 127.0.0.1 --port 8765 --data-dir ./server-data
```
在另一终端运行：
```bash
python3 demo_client.py --base-url http://127.0.0.1:8765 --concentration 1.5
```
自动测试：
```bash
python3 test_system.py
```
代码采用脚本目录布局，应在本目录执行这些命令。服务支持最多八个HTTP处理线程，计算流程按服务锁串行执行，健康检查不等待计算锁。超时、请求大小限制和并发上限用于限制资源消耗；这不是生产集群调度系统。远程部署应在受控网络中使用TLS反向代理和访问认证。
## 单文件界面
`index.html` 包含全部样式、脚本和示例数据，没有外部前端依赖、空行或注释。双击可查看界面、预览和框选图像、导入与下载报告；真实检测需要现有Python后端。
启动 `python3 server.py` 后，在浏览器访问 `http://127.0.0.1:8765/`，即可在同域页面完成批次标定和现场检测。新增的页面路由仅返回固定HTML文件，不提供任意目录读取，也不启用跨域访问。
首次体验时，进入批次标定，点击“载入模拟标准品”及“执行标定”，成功后点击“用于检测”，再点击“载入模拟样本”和“提交检测”。模拟批次不等于真实试剂标定。查看内置示例只加载已有报告，不会伪装成接口运算。
图像在浏览器内解码和选区缩放，转为48×6的RGB数组发送。标准品上传已裁剪图像；待测图像可拖动选区。输入图片只进行浏览器几何处理，不代替拍摄装置标定。报告图像按后端PPM数据解码到Canvas显示。
“重试原请求”复用原端点、样本编号、时间戳和像素内容；“新建检测”生成新编号。页面只缓存服务地址、设备编号和已知批次编号，不缓存照片或报告历史。报告导入不验证来源身份；SHA256也不是数字签名。

| index.html | 三个操作界面、图像选区、接口调用与报告展示 |

| sampling.py | 响应去冗余、像素选择与样本权重 |
| wire.py | 二进制报文编码、解析与CRC校验 |
| fitting.py | 有界浓度拟合、质量检查与迭代记录 |
| reports.py | 结果整理、PPM图像和报告摘要 |
| repository.py | SQLite事务、批次锁定与数据关联检查 |
| validation.py | 数值、标识、JSON和请求错误校验 |
| service.py | 批次注册、采集和检测流程 |
| server.py | HTTP服务和并发请求限制 |
| runtime.py | 本机服务启动与关闭 |
| demo_client.py | HTTP客户端及独立模拟输入 |

内部采用 `BatchCalibration`、`sample_pixels`、`fit_concentration`、`DetectionService` 等工程命名。外部接口沿用 `/v1` 路径以及 `core_count`、`core_rmse` 字段，避免已有客户端因内部重命名而失效。
## 接口
POST请求使用 `Content-Type: application/json`，响应为UTF-8 JSON。错误格式为 `{"error":"错误说明"}`；400表示输入错误，404表示批次或路由不存在，409表示数据冲突，413表示请求过大，415表示媒体类型不支持，503表示存储不可用或请求线程已满。JSON重复字段、NaN和Infinity均被拒绝。
| 接口 | 输入及返回 |
|---|---|
| GET /health | 返回服务状态 |
| POST /v1/batches | 提交批次、标准品及图像，返回标定参数与RMSE |
| POST /v1/captures | 提交外部RGB图像及样本信息，返回Base64报文 |
| POST /v1/packets | 接收网关提交Base64报文，返回检测报告 |
| POST /v1/analyze | 联调入口，依次执行采集与分析并返回报告 |
每个完整请求体不超过4 MiB，图像宽高为2至256，图像结构为 `height × width × 3` 数组，通道为0至255的有限数值。JPEG或PNG须由采集前端解码后提交，本服务不读取客户端路径。
批次请求示意：
```json
{
  "batch_id": "BATCH001",
  "version": "model-v1",
  "demo": false,
  "parameters": {"recovery_factor": 1.0},
  "standards": [
    {"concentration": 0.0, "image": "完整RGB数组"},
    {"concentration": 1.0, "image": "完整RGB数组"},
    {"concentration": 3.0, "image": "完整RGB数组"}
  ]
}
```
示意中的字符串需要替换为真实数组，完整可运行请求见 `demo_client.py`。至少需要三个不同浓度标准品，最多八份。先拟合对数强度获得初值，再以像素强度残差执行带步长回退的双参数最小二乘修正，求得光学增益和背景。标定RMSE不得超过2个像素灰度级，该阈值是当前实现的质量门限，不代表经实验室验证的验收标准。
`parameters` 支持 `diffusion`、`velocity`、`binding_rate`、`dissociation_rate`、`capacity`、`recovery_factor`、`max_concentration`。前五项采用模型网格及时间尺度的无量纲参数，不能直接代入有量纲实验常数。最终求解上下限取实际标准品的浓度最小值和最大值。批次一经保存，标定配置和原始标准品数据均不可通过同名请求覆盖；修订需使用新批次编号。
采集请求示意：
```json
{
  "sample_id": 1001,
  "device_id": "DEV00001",
  "batch_id": "BATCH001",
  "timestamp": 1793581200,
  "image": "完整RGB数组",
  "roi": [0, 0, 48, 6],
  "inverse_affine": [1, 0, 0, 0, 1, 0],
  "location": {"latitude": 31.2304, "longitude": 121.4737}
}
```
`roi`、`inverse_affine`、`timestamp`、`location`可省略。ROI是校正坐标系中的 `[x,y,width,height]`，逆仿射将校正坐标映射回原图；越界采样拒绝，不会自动补零。输出标准图像为48×6。样本编号为正32位整数；设备与批次编号为1至8位ASCII字母、数字、下划线或连字符。前端重试应保持原始请求不变。
网关转发请求：
```json
{"packet_base64":"采集接口返回的packet_base64"}
```
同一设备和样本编号下，重复报文返回原报告，不同报文返回409。原图先到或报文先到都执行交叉一致性检查，冲突事务回滚。报告保存后保持不变；报文先到时没有定位元数据，报告中的地点为null，后续采集记录不会改写已有报告。内部数据库保留原图、标准图、标定输入、报文、拟合历史与报告。SHA256用于检测内容变化，不提供身份认证或数字签名。
## 报文
报文按网络字节序编码：魔数4字节、版本1字节、样本编号4字节、时间戳4字节、设备编号8字节、批次编号8字节、采样数量1字节、采样点各7字节、CRC32共4字节。每点含X与Y各2字节、RGB各1字节。当前选择四个响应点、一个质控点和一个背景点，共76字节。HTTP中的Base64为104字符，卫星载荷限制按解码后的二进制长度核算。
原始图像保存在现场端，只有压缩报文适合转交北斗终端。本服务提供载荷协议和HTTP接收接口，不包含具体终端型号的串口指令、真实卫星发送、确认重传或运营商接入。独立网关部署时需另行传送或关联定位等扩展元数据。
## 数值与结果范围
模型采用一维显式对流扩散和可逆结合更新，输出简化的非竞争型检测线及固定参考质控线。浓度导数与离散状态同步传播。批次扩散、结合和解离参数保持固定，检测阶段只拟合浓度；不能由六个采样点推断全部物理参数。
采样先剔除参考图像中重复的8位RGB响应，减少同类量化信息重复传输，再按浓度敏感度和点间距离执行遗传搜索。采样随机种子由保存的批次配置确定，同一批次输入可重复获得相同采样位置。求解器采用有界黄金分割搜索，适用于当前单变量单峰残差模型，不保留无效叠加的优化步骤。若将模型改为多参数或多峰问题，需同时替换求解器和相应验证。
质量检查包含求解终止状态、加权残差、全部采样像素RMSE、检测线覆盖、质控线与背景检查。达到上限不会自动判定成功；触及标定上边界或非零下边界时返回无效结果，以免把截断值当作有效定量。无效报告的 `concentration` 为null，具体原因见 `solver.reasons`；`raw_concentration`仅供诊断。
回收率校正采用 `浓度 = 初始浓度 × recovery_factor`。该字段填校正乘数，不直接填回收率百分比。输出单位为提取液ng/mL，未给定样本质量、提取体积和稀释倍数时不换算成组织残留ng/g。报告中的PPM是模型计算图像，不是采集照片。
模拟数据用于验证软件处理链，不证明真实试剂的检测精度。当前实现未覆盖竞争法反应、透视校正、温度补偿或任意显色时间；接入实际试剂前需独立标定及留出样本验证。`demo=false`只标识调用方提供了外部标准品，不意味着完成方法学认证。
数据库使用版本2。默认目录与旧版分开；遇到无版本元数据的旧数据库会停止加载并保留原文件，应另选新目录。未实现自动迁移，不能直接用旧标定配置替代新范围检查。
